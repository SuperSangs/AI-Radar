# AI Radar 内容采集与公众号创作方案

日期：2026-09-09。状态：统一设计稿；不是已上线功能说明。

## 1. 端到端链路

X 官方账号 / 重点人物 / 全网发现 → 原始内容与指标快照 → 相关性过滤 → 重复内容合并 → 分类与排序 → 统一内容快照 → DeepSeek 今日 X 情报 → 用户选择主题或帖子 → DeepSeek 成稿 → Image2 国内接口配图 → 公众号排版与预览 → 保存公众号草稿箱。

所有阶段保留来源 ID、内容版本和时间，文章与总结可以追溯到原帖。文章生成不以二次总结代替原始资料。

## 2. 采集与预算

- 70 为每日新发现 X Post ID 的目标上限，不是必须展示的条数，也不是包含所有重读的账单保证。
- 初始额度：官方 15、重点人物 25、全网发现 30。官方重大更新可以借用发现额度；保留发布高峰所需额度。
- 分批增量采集，官方建议每两小时检查，人物与发现分散到每日多个时段。达到预算后停止新增读取，并展示覆盖截至时间及未完成分页。
- 新内容默认滚动 24 小时；历史内容只能在手动历史范围查看。恢复中断时不得把采集时间当作发布时间。
- 预算账本分别记录新 ID、返回资源次数、指标重读、请求次数及可获取的实际用量。跨 UTC 日的重读需要重新计入风险预算。
- 搜索过滤、重复结果、分页均可能消耗资源；清洗后允许少于 70。实际成本以服务端账单为准，不承诺固定金额。
- 官方账号身份在接入前核验；核心覆盖 OpenAI、Claude/Anthropic、Gemini/Google DeepMind。保留现有人物名单，其他官方账号作为扩展项。
- 官方博客作为免费补充消息源独立标识，不冒充 X 帖子、不编造 X 指标。

## 3. 内容质量与重复处理

- 官方模型、API、产品能力、研究更新优先；活动、招聘、纯广告不自动进入重点信息。
- 讨论收录有原创分析的 Article、长帖、实测与方法论。篇幅长或浏览高本身不代表质量高。
- 强 AI 相关性、实质信息和来源可追溯作为准入条件；热度、时效、内容深度用于准入后的排序。
- 确定性去重：Post ID、编辑历史、同一作者同一线程及相同正文。
- 同一外链或近似文本先归为候选组；语义审核判断是否增加新证据、结论或反对意见。新增观点保留为事件内独立观点，避免误删。
- 事件默认一个主卡，展开查看不同观点；各帖指标归属各自原帖，不叠加成虚假的单帖热度。
- 过滤与合并保留原因，可回溯纠正。

## 4. 指标

- 保存 X 返回原始 public_metrics 与 metrics_fetched_at；缺失和零值分开。
- 转发、引用、点赞、曝光分别展示，曝光不称为独立人数，内部排序分不冒充平台指标。
- 对活跃讨论和官方重点帖目标每两小时批量刷新，受预算、接口和错误退避限制；逾期明确显示时间。
- 更新响应按时间排序，防止较旧响应覆盖较新快照；失败不清零。
- 不能保证与用户稍后打开的 X 页面逐秒一致。验收比较相同 Post ID、相近时间的原始响应。

## 5. 今日 X 情报

- 与列表共享不可变内容快照：所有最近 24 小时通过筛选的 X 内容均参与分析，取消原来的最多 24 条 X 抽样限制。
- 逐条提取事实、观点、证据、分歧与来源 ID，再聚合事件和主题；正文不完整需标记。
- 展示实际覆盖条数 / 应分析条数、事件数、生成时间和数据截至时间。部分失败不标为全量完成。
- 主题区分传播热度、官方重要性及独立观点数量；不将搬运数量当讨论广度。
- 输出今日事件、热门分歧、内容选题、学习建议，每项附来源。
- 新内容快照触发增量分析；微小指标波动不重写全文。缓存键包含内容、来源、提示词和模型版本。

## 6. 公众号创作

- 单卡“写成公众号”、主题“围绕主题写作”、顶部“创作中心”和“公众号后台”。
- 默认 1200–1800 字、3 个备选标题、摘要、1 张封面和 1–2 张正文图；支持短稿和自定义角度。
- 输入为选中内容的原文、官方佐证及来源快照；需要额外付费读取时计入统一预算。
- 生成结构化稿件：事实与观点分开，缺少依据标注待核实；来源页中不完整信息可查看。
- 排版使用固定模板，手机预览，可编辑正文、换标题、单独重做图片。
- 数据图由核实数据绘制；Image2 生成封面/插画，中文标题可由程序叠加。
- 后台任务持久化，关闭窗口不丢失；步骤完成后落盘，失败恢复不重跑全部。
- 保存草稿是显式操作，正式发布由用户在公众号后台完成。重复点击不重复建稿，后续修改更新已有草稿。
- 上传超时导致结果不明时进入待核对状态，先查询/核对，不盲目重试创建。

## 7. Image2 国内接口边界

文档：https://tcnxnzs113h4.feishu.cn/wiki/QyYTwvfckiTiEIkr1jZc2gNAn6d

当前文档未读取成功，以下为待核验项，不能据此宣称接口已接通：供应商、国内 Base URL、实际模型 ID、鉴权方式、提交路径、同步/异步模式、任务查询、图片返回形式、尺寸与格式限制、错误码、超时、重试和计费规则。

实现使用独立图片服务适配器，对业务暴露提交、查询、取图和错误状态。若供应商不支持其中某项，适配器按真实能力实现；不猜测 OpenAI 兼容性，也不自动切换海外节点。

计划服务端配置名：IMAGE_PROVIDER、IMAGE_API_BASE、IMAGE_MODEL、IMAGE_API_KEY；它们是本项目拟定配置，不是供应商已确认参数。缺 Key 时显示未配置，不生成占位图冒充结果。

密钥仅保存在服务端私密配置，日志脱敏；只向用户确认的供应商发送图片提示词和选定参考素材。生成结果保存到项目素材存储，避免依赖临时 URL。

## 8. 微信适配

核验目标账号草稿与素材接口权限、AppID、AppSecret、IP 白名单。完成封面素材、正文图片、图文 HTML 和草稿创建/更新；核对返回记录后才显示同步成功。

无接口权限时仍保留生成、预览和图文导出能力。公众号后台入口先打开后台首页，不承诺不存在或依赖过期登录态的直达编辑链接。

## 9. 交付阶段与验收

1. 采集清洗、70 条预算、准确指标归属与全量总结：固定样本验证时效、重复合并、观点保留、官方优先、预算不越界、总结覆盖率。
2. 创作中心、成稿、排版、任务恢复：使用固定内容样本验证引用和失败恢复，不依赖图片或微信密钥。
3. 核对 Image2 文档后接入国内适配器：真实 Key 到位后小规模生图联调，验证重复提交与超时处理。
4. 微信账号权限与凭据到位后进行一篇测试草稿同步，核对封面、图片、版式与重复操作；不自动发布。
